# 실물 Detection · 파지 위치 접근

관제센터 Detection은 YOLO로 물체를 식별하고 MID-360으로 위치를 구한다. **물체가 책상 반대편에 있으면 도달 가능한 책상 면으로 Nav2가 돌아간 뒤 접근한다.** 책상 모델이 아직 없으면 확인된 3D 물체 좌표로 출발하고, 모델이 생기면 접근 면을 선택해 경로를 바꾼다. 가까운 쪽에서 닿지 않는 물체를 향해 직진하며 상판을 가로지르려고 하지 않는다. Gazebo용 팔 이동 노드는 실행하지 않는다.

## 사용

1. Head D435·MID-360·차체 입력과 SLAM / 저장 지도 위치추정을 시작한다.
2. Detection에 물체 이름을 입력하고 **찾아서 이동**을 누른다. 이름 선택과 이동 예약을 하나의 요청으로 처리한다. 사과/green_apple/apple, 복숭아/peach, 토마토/tomato, 환타캔/fanta_can, 컵/cup, 바나나/banana를 지원한다.
3. 3D 좌표가 아직 없어도 이동을 예약할 수 있다. 물체 박스에 대응하는 서로 다른 LiDAR 점 3개 이상, 위치 추정 3회의 12cm 이내 일치가 확인되면 Nav2를 시작하거나 활성화를 기다린 뒤 해당 좌표로 이동한다. 같은 종류가 여러 개면 처음에는 가까운 것을 선택하고 이후 25cm 안의 관측만 같은 대상으로 취급한다. 화면에는 관측만 하는 상태와 이동 요청됨을 구분해 표시한다. 페이지 새로고침·서버의 이름 복원만으로 이동을 시작하지 않는다.
4. **책상 추가 이격**은 기본 0m다. 이는 물체 중심까지의 거리가 아니라 실제 로봇 형상과 책상 사이에 더 남길 거리다. 0이면 책상 높이에 걸리는 차체·랙·현재 팔 형상까지 최대한 접근하도록 계획한다. 저면 차체가 책상 아래로 들어갈 수 있는 공간과 책상 높이의 랙을 구분한다.
5. **도달 가능한 책상 면 선택 → Nav2로 해당 면 바깥 준비 위치 이동 → 필요한 가장자리 재측정 → 물체 방향 정렬 → 실제 몸체 기준 정밀 접근** 순서다. 책상 모델이 없을 때는 먼저 물체 XY로 이동한다. 이동 중 모델이 생기면 기존 Nav2 이동의 종료를 확인하고 접근 면의 목표로 전환한다. 알려진 책상에서 파지 후보를 만들지 못하면 재관측하며 멈추고 원인을 표시한다.
6. Detection과 NAV 양쪽에 3D 좌표 대기·좌표로 이동·방향 정렬·3D 물체 접근·책상 정밀 접근 단계를 표시한다. 지도에는 3D 물체 목표와 실제 Nav2 목표를 먼저 표시하며, 책상 모델이 생기면 윤곽과 최종 파지 위치도 표시한다. 접근 취소·NAV 이동 취소·검출 중지는 예약된 이동과 진행 중 접근을 취소한다.

## Nav2 연결과 충돌 판정

`/navigate_to_pose` 엔드포인트 존재만으로 준비 완료라 하지 않는다. `bt_navigator`, `controller_server`, `planner_server`의 lifecycle이 모두 active이고 최근 응답인지 확인한 뒤 목표를 보낸다.

책상 모델이 없을 때의 첫 이동은 `navigate-to-detection-target.xml`에서 `DetectionTarget` NavFn 플래너와 `GraspApproach` DWB 컨트롤러를 사용하고 2Hz로 다시 계획한다. 요청 목표는 3D 물체 XY 그대로다. 물체·상판 자체가 2D 지도에서 점유 셀이므로, 이 플래너에만 1m 탐색 tolerance를 주어 물체에 가장 가까운 도달 가능한 빈 경로 끝점을 찾는다. 이 값은 마지막 정지 거리나 충돌 여유가 아니다. Nav2 경로 끝 도착을 전체 접근 완료로 처리하지 않고 3D 좌표 피드백 접근으로 이어간다. 이미 물체 전방 도달 범위 안이면 정밀 접근부터 시작한다. 책상 모델이 있으면 이 원시 좌표 목표보다 책상 접근 면 선택이 우선한다.

책상 준비 위치 이동은 `navigate-to-detection.xml`과 `TableStage` NavFn 플래너를 사용한다. 이 플래너의 tolerance는 5cm로 두어 반대편 목표를 가까운 쪽 빈 셀로 대체하지 않게 한다. Nav2 도착 뒤에도 선택한 면 바깥인지, 준비 위치 20cm 안인지 확인한다. 기존 `ObstacleFootprint`의 전체 3D 형상을 한 장의 XY 외곽으로 누르는 판정은 `GraspApproach`에서 제외한다. 높이가 다른 책상·차체·랙이 그 투영에서 겹쳐 모든 후보가 시작부터 거부되는 문제를 피하기 위한 것이다. `BaseObstacle`과 경로 평가를 유지하며 모든 차체 명령은 기존 3D 보호와 watchdog을 통과한다. 일반 NAV에는 기존 XY 외곽 검사도 적용한다.

3D 물체 위치 추정과 책상 면 추정은 서로 다른 작업이다. `head_lidar.locate`는 책상 추정 결과 없이 물체 좌표를 반환한다. 책상 추정은 이동 중 별도 worker에서 수행하며 실패가 물체 좌표를 무효화하지 않는다. 책상 모델이 없는 동안에는 저장 물체 좌표 쪽 접근을 계속한다. 물체 좌표 2cm 이내로 정렬하거나, 물체 전방 도달 범위 안에서 실제 몸체 충돌 보호가 더 이상 전진을 허용하지 않으면 `at_target`으로 물체 앞 도착을 표시한다. 이 상태는 정밀 파지 위치 확정이나 팔 파지 완료와 구분한다. 알려진 책상에서 접근 후보를 못 만들면 직진으로 돌아가지 않고 최대 15초 재관측한 뒤 원인을 표시한다. 정밀 이동·방향 정렬이 3초간 진행하지 못하면 아래 후진·회전 복구로 전환한다.

YOLO JSON·CameraInfo·LiDAR·오도메트리와 TF는 **별도 `inha_detection_inputs` ROS 노드와 단일 executor 스레드**로 받는다. 관제 영상 JPEG·점군 시각화·HTTP 처리와 같은 executor를 사용하지 않는다. 별도 스레드에서 웹 노드를 다시 spin하는 방식도 사용하지 않는다. 점군 변환은 이 입력 노드의 20Hz 타이머에서 처리하고, 촬영 시각의 TF를 정확히 사용한다. 처리 지연을 감추려고 최신 TF로 바꾸거나 관측 시각을 새로 쓰지 않는다. 책상 점군 한 프레임의 TF 대기가 물체 점군 처리를 막지 않도록 재시도 프레임을 뒤로 보내며, odom/시각 초기화에서는 epoch가 다른 변환 결과를 버린다. 물체 현재 상대 위치와 정지 확인도 이 입력 노드의 TF·오도메트리를 사용한다.

`detection_control.inputs`에는 YOLO·LiDAR·CameraInfo·오도메트리 수신 수와 원본 시각 지연, 변환된 점군 수, TF 재시도·만료·입력 오류를 표시한다. 관측 중에도 이동 요청이 없으면 관측 상태로 명시하며, 이동을 예약한 동안에는 실제 3D 좌표를 기다리는 이유와 위치 확인 횟수를 보여준다.

일반 NAV·물체 XY 이동·책상 준비 위치 이동 모두 전진과 제자리 회전을 우선한다. DWB 최소 x 속도는 0m/s로 두어 평상시 주행 후보에서 후진을 제외한다. `PoseProgressChecker`는 5cm 이동 또는 0.10rad 회전을 진행으로 인정하고, 6초간 둘 다 없으면 복구를 시작한다. 세 BT의 이동 복구는 `Fallback` 안에서 왼쪽 45° 회전 → 오른쪽 45° 회전 → 20cm 후진(0.05m/s) 순서로 시도한다. 회전 하나가 성공하면 후진 없이 재계획하며, 양쪽 회전이 모두 실패해야 후진에 진입한다. costmap 갱신·1초 대기도 제한된 복구에 포함한다. 각 동작의 허용 시간은 6초, BT 재시도는 최대 6회다. Nav2 자체 costmap 검사와 기존 3D 보호가 복구 명령에도 적용된다. 후보를 모두 소진하면 도달 범위 안인 다른 책상 면으로 다시 계획한다.

마지막 정밀 접근은 Nav2와 명령을 동시에 발행하지 않는다. Nav2가 끝난 상태에서 3초간 정밀 이동·정렬에 진전이 없거나 도킹 옆 오차가 남으면 `recovering`으로 전환한다. 물체 쪽 회전 방향부터 좌우 45° 제자리 회전(최대 0.20rad/s)을 차례로 시도하고, 두 방향 모두 진행하지 못할 때만 최대 20cm 후진(0.05m/s)을 시도한다. 1.2초간 진전이 없거나 각 동작의 6초 제한에 도달하면 다음 후보를 사용한다. 유효한 회전·후진 진행이 생기면 그 공간을 사용해 재계획한다. 동작 전환·재접근 전 정지를 확인하며, 복구 이동은 동일한 `/cmd_vel` 3D 보호와 watchdog을 통과한다. 원본 LiDAR 목표를 유지한 채 Nav2 준비 위치로 재접근하고, 정밀 복구는 접근 요청당 최대 2회다. 좌우 회전과 후진 모두 막히면 원인을 표시하고 정지한다.

일반 주행·책상 우회 경로는 통로 중앙을 선호하도록 local/global inflation 반경 1.50m, 비용 감쇠 계수 2.0의 완만한 비용 구배를 사용한다. `prepare-navigation-profile.py`가 이 범위를 몸체 내접 반경으로 줄이지 않도록 하고, 선택된 별도 프로필도 최소 반경 1.50m·최대 감쇠 계수 2.0을 적용한다. 실제 몸체 외곽과 추가 충돌 여유 0cm는 유지한다. `FollowPath`의 `BaseObstacle.scale`은 0.03, 책상 준비 위치용 `GraspApproach`는 0.01로 두어 비용 구배가 지정 목표 도착 자체를 밀어내지 않게 한다. 마지막 정밀 접근의 `/cmd_vel` 제어와 3D 보호는 기존 방식이다. 장애물이 비대칭이거나 통로가 매우 넓으면 경로가 정확한 기하학적 중앙선과 일치하지 않을 수 있다.

실패 시 DWB 충돌·진행 불가 등 수신한 원인을 함께 표시한다. inflation 반경의 최솟값은 float32 외곽 전송 반올림을 고려한 몸체 내접 반경 이상으로 유지한다.

## 책상 가장자리와 파지 위치

`head_lidar.py`는 물체 위치용 `/mid360/points_obstacles`와 책상 경계용 `/mid360/points_filtered`를 각 측정 시각에 `odom`으로 변환한다. 경계용 점군에는 바닥에 맞은 광선도 포함해, 상판 스캔이 단순히 가림으로 끊긴 곳과 실제 가장자리를 구분한다.

`grasp_approach.py`는 기존 `surface_geometry`의 수평 면·광선 경계 추정을 재사용한다. 물체 아래 상판의 각 면에서 파지 도달 거리를 계산해, 가까운 면에서 닿지 않으면 옆면·반대편 준비 위치를 선택한다. 경계 관측 비율 0.4 미만인 면도 우회 준비 위치 후보로 사용하지만 정밀 접근에는 사용하지 않는다. 이 경우 도착 이후의 LiDAR로 같은 방향의 실제 경계가 0.4 이상 관측되어야 파지 위치를 확정한다. 15초 안에 확인되지 않으면 정지하고 이유를 표시한다. 카메라가 물체를 계속 볼 필요는 없다.

현재 팔 실측 관절을 적용한 공용 `RobotGeometry`의 OBB를 상판 높이 구간과 교차시켜, 그 구간에서 실제 로봇이 차지하는 범위로 최소 가장자리 거리를 계산한다. 상판 아래 차체의 전체 XY 외곽을 상판과 충돌한다고 간주하지 않는다. 계획용 상판 두께 구간은 윗면 아래 4cm이며, 실제 두께·다리·의자·팔과의 충돌은 현재 3D 관측과 전체 몸체 보호가 별도로 판단한다. Nav2 준비 위치는 최종 물체 방향과 같은 직선 위에 놓고, 차체가 선택한 면 바깥이면서 이 직선의 접근 영역 안에 있을 때만 Nav2를 건너뛰고 정밀 제어한다.

파지 위치에서는 물체가 정면에 오도록 yaw를 계산한다. 물체가 설정된 전방 도달 거리(기본 0.50m) 안에 있는 후보만 선택한다. Nav2 준비 거리는 책상 끝에서 차체 중심까지 기본 0.65m다. 이것은 마지막 정지 거리가 아니다. 최종 정밀 접근은 최대 0.06m/s, 0.25rad/s이며, 이동 전 0.035rad 이내로 방향을 맞춘다. 최종 위치 오차 8mm 이내에서 별도 최종 정렬로 전환한다. 책상 파지 위치·원시 물체 좌표·실제 몸체 한계 도착 모두 물체 방향 오차 0.02rad(약 1.1°) 이내와 선속도 0.01m/s·각속도 0.02rad/s 이하를 0.6초 유지해야 완료한다. 정렬 중 위치가 벗어나면 접근 위치를 다시 보정한다. 이는 차체 도착 기준이며 팔 IK·파지 성공을 의미하지 않는다.

최종 정렬이 3초간 진행되지 않아도 좌우 회전을 먼저 시도한다. 두 회전 경로가 모두 막혔을 때만 5cm 후진으로 회전 공간을 확보하고, 확보한 위치에서 물체 쪽으로 먼저 정렬한 뒤 Nav2 재접근을 수행한다. 기존 최대 2회 복구·120초 전체 제한에 포함하며, 도달할 수 없으면 미완료 오류를 표시한다. 충돌 보호를 무시해 회전을 강제하거나 방향 미정렬 상태를 완료로 보고하지 않는다. 상태의 `orientation_required`, `heading_tolerance`, 목표의 `heading_error`·`heading_aligned`로 정렬 조건과 오차를 확인할 수 있다.

일반 NAV도 `StoppedGoalChecker`로 위치 5cm·yaw 0.02rad 이내와 실제 정지를 함께 확인한다. Nav2 footprint는 모든 실제 형상 꼭짓점을 포함하는 볼록 다각형으로 생성·갱신해 직사각형의 빈 모서리를 줄인다. 3D guard의 실제 차체·팔 크기와 추가 이격 0cm 설정은 유지한다.

## 카메라에서 사라진 뒤

YOLO 촬영 시각의 optical 프레임에 LiDAR를 K/D로 투영한다. 대표 위치는 박스 중앙의 가까운 군집 안 실제 LiDAR 점이며 RGB-D 깊이로 바꾸지 않는다. 촬영 시각, LiDAR 시각, 물체 점·책상 경계·차체 목표를 `odom`에 저장한다. 이동을 시작하면 그 기준점을 고정한다. 물체가 카메라 시야에서 사라져도 현재 오도메트리로 남은 위치와 물체 방향을 계산해 계속 접근한다. SLAM 보정은 지도 표시와 Nav2 준비 목표 변환에만 반영한다.

이동 시작에 사용할 저장 위치는 30초 이내 확인한 것이어야 한다. 좌표 없이 이동을 예약하면 30초 동안 YOLO 3D 관측을 기다린다. 이후 접근은 최대 120초 동안 저장 위치를 사용한다. ROS 시각·오도메트리가 불연속이면 좌표를 버리고 다시 관측한다. 시야 밖에서 물체가 옮겨졌다면 저장 좌표 지우기로 다시 선택한다. 목표 기억과 현재 장애물 판단은 별개다. `/cmd_vel → 3D guard → actuator watchdog → Tracer` 경로와 몸체 기준 추가 충돌 여유 0cm를 유지한다. 후진·회전 복구도 같은 전체 접근 제한 시간에 포함한다.

## 설정과 인터페이스

`config.json` / `config.example.json`의 detection 설정:

- `objects_topic`, `odom_topic`, `cloud_topic`, `surface_topic`, `camera_info_topic`: YOLO JSON·오도메트리·물체·책상·원본 RGB 내부 보정 입력.
- `table_clearance`: 기본 추가 이격 0m, UI 설정 0~0.1m.
- `stage_edge_distance`: Nav2 준비 위치의 가장자리 거리, 기본 0.65m.
- `grasp_max_forward`: 물체 전방 도달 범위, 기본 0.50m. 실제 파지 가능성은 후속 실물 IK에서 판단한다.

`POST /api/detection`은 start/stop/select(label)/find_and_approach(label, edge_clearance)/approach(edge_clearance)/cancel/clear를 지원한다. `select`는 관측 대상을 고르는 기존 인터페이스이며, 화면의 찾아서 이동은 `find_and_approach`로 이름 적용과 이동 예약을 함께 처리한다. HTTP 202는 접수이며 실제 결과는 SSE detection_control에 표시한다. 이전 distance 필드를 보낸 화면에는 새로고침 안내를 반환한다.

`detection_control`과 `/detection/closed_approach/status`에는 Nav2 활성화·책상 계획·방향 정렬·정밀 접근 상태, 저장 목표와 촬영 시각, 책상과 파지 목표가 포함된다. `/detection/closed_approach/target`은 실제 촬영 시각과 odom 좌표를 보존한다.

관제센터와 Nav2를 재시작해야 새 코드와 GraspApproach 컨트롤러가 반영된다. 실행 중 지도는 먼저 pose graph로 저장하고 `--mapping --resume-mapping-params <profile.yaml>`로 이어 읽을 수 있다. 복원 프로필은 최초 SLAM 시작에만 사용하고, 이후 화면의 초기화는 기본 프로필로 새 지도를 시작한다. 이전 이동·접근 명령을 자동으로 재실행하지 않는다.
