# 실물 Detection · 파지 위치 접근

관제센터 Detection은 **Head 카메라 YOLO로 먼저 물체를 잡고 영상 방향으로 접근한다. 물체의 3D LiDAR 좌표는 출발 조건이 아니다.** 이동 중 MID-360 좌표를 확보하면 저장 좌표 기반 접근으로 전환한다. 먼 목표의 경로 이동과 책상 반대편 우회에는 Nav2를 쓰고, 가까운 구간은 오도메트리와 저장 LiDAR 좌표로 직접 제어한다. 책상 모델은 별도로 계산하며 실제 접근 후보가 생겼을 때 경로에 반영한다. 모든 속도는 기존 3D guard와 actuator watchdog을 통과한다.

## 사용

1. Head D435·MID-360·차체 입력과 SLAM / 저장 지도 위치추정을 시작한다.
2. Detection에 물체 이름을 입력하고 **찾아서 이동**을 누른다. 이름 선택과 이동 예약을 하나의 요청으로 처리한다. 사과/green_apple/apple, 복숭아/peach, 토마토/tomato, 환타캔/fanta_can, 컵/cup, 바나나/banana를 지원한다.
3. 3D 좌표가 아직 없어도 YOLO 검출만으로 접근을 시작한다. CameraInfo의 K/D와 촬영 시각의 카메라→차체 TF로 물체 중심의 수평 방향을 구한다. 먼저 방향을 맞추고 최대 0.04m/s·0.18rad/s로 접근하며 영상으로 물체 거리를 만들지 않는다. 같은 종류가 여럿이면 처음에는 신뢰도가 높은 박스를 고르고 이후 영상 위치로 이어 추적한다. 이동 중 물체 박스에 대응하는 서로 다른 LiDAR 점 3개 이상의 가까운 군집이 잡히면 즉시 좌표를 저장하며 3회 연속 확인은 요구하지 않는다. 정지 0.2초 후 저장 좌표 제어로 전환한다. 최초 3D 좌표 확정 이후에는 25cm 안의 관측만 같은 대상으로 취급한다. 화면에는 관측만 하는 상태와 이동 요청됨을 구분해 표시한다. 페이지 새로고침·서버의 이름 복원만으로 이동을 시작하지 않는다.
4. **책상 추가 이격**은 기본 0m다. 이는 물체 중심까지의 거리가 아니라 실제 로봇 형상과 책상 사이에 더 남길 거리다. 0이면 책상 높이에 걸리는 차체·랙·현재 팔 형상까지 최대한 접근하도록 계획한다. 저면 차체가 책상 아래로 들어갈 수 있는 공간과 책상 높이의 랙을 구분한다.
5. **도달 가능한 책상 면 선택 → Nav2로 해당 면 바깥 준비 위치 이동 → 필요한 가장자리 재측정 → 물체 방향 정렬 → 실제 몸체 기준 정밀 접근** 순서다. 책상 모델이 없을 때는 먼저 물체 XY로 이동한다. 이동 중 모델이 생기면 기존 Nav2 이동의 종료를 확인하고 접근 면의 목표로 전환한다. 책상 파지 후보가 없으면 좌표 접근을 유지하며 모델을 재관측한다. 실행 가능한 후보를 먼저 계산한 뒤에만 기존 목표를 취소하고 우회 목표로 바꾼다.
6. Detection과 NAV 양쪽에 3D 좌표 대기·좌표로 이동·방향 정렬·3D 물체 접근·책상 정밀 접근 단계를 표시한다. 지도에는 3D 물체 목표와 실제 Nav2 목표를 먼저 표시하며, 책상 모델이 생기면 윤곽과 최종 파지 위치도 표시한다. 접근 취소·NAV 이동 취소·검출 중지는 예약된 이동과 진행 중 접근을 취소한다.

## Nav2 연결과 충돌 판정

`/navigate_to_pose` 엔드포인트 존재만으로 준비 완료라 하지 않는다. `bt_navigator`, `controller_server`, `planner_server`의 lifecycle이 모두 active이고 최근 응답인지 확인한 뒤 목표를 보낸다.

책상 모델이 없을 때의 첫 이동은 `navigate-to-detection-target.xml`에서 `DetectionTarget` NavFn 플래너와 `GraspApproach` DWB 컨트롤러를 사용하고 2Hz로 다시 계획한다. 요청 목표는 3D 물체 XY 그대로다. 물체·상판 자체가 2D 지도에서 점유 셀이므로, 이 플래너에만 1m 탐색 tolerance를 주어 물체에 가장 가까운 도달 가능한 빈 경로 끝점을 찾는다. 이 값은 마지막 정지 거리나 충돌 여유가 아니다. Nav2 경로 끝 도착을 전체 접근 완료로 처리하지 않고 3D 좌표 피드백 접근으로 이어간다. 이미 물체 전방 도달 범위 안이면 정밀 접근부터 시작한다. 책상 모델이 있으면 이 원시 좌표 목표보다 책상 접근 면 선택이 우선한다.

책상 준비 위치 이동은 `navigate-to-detection.xml`과 `TableStage` NavFn 플래너를 사용한다. 이 플래너의 tolerance는 5cm로 두어 반대편 목표를 가까운 쪽 빈 셀로 대체하지 않게 한다. 도킹용 준비 위치의 도착 판정은 XY 20cm로 완화하며 준비 위치에서의 yaw 정렬은 요구하지 않는다. 최종 물체 방향 정렬은 정밀 제어가 수행한다. 기존 `ObstacleFootprint`의 전체 3D 형상을 한 장의 XY 외곽으로 누르는 판정은 `GraspApproach`에서 제외한다. 높이가 다른 책상·차체·랙이 그 투영에서 겹쳐 모든 후보가 시작부터 거부되는 문제를 피하기 위한 것이다. `BaseObstacle`과 경로 평가를 유지하며 모든 차체 명령은 기존 3D 보호와 watchdog을 통과한다. 일반 NAV에는 기존 XY 외곽 검사도 적용한다.

책상 모델이 없는 물체 좌표 이동도 물체 0.9m 안·방향 오차 0.6rad 안에서 `point_handoff`로 전환한다. 자신의 Nav2 목표 종료와 실제 정지 0.4초를 확인하고 저장 좌표 근접 제어로 이어간다. Nav2 최종 복구 소진까지 기다리지 않는다.

도킹은 Nav2 성공·최종 실패를 기다리는 대신 주행 중에도 3D 정밀 접근으로 전환할 수 있다. 선택한 책상 면 바깥의 준비 위치 20cm 안이거나, 실제 경계를 확인한 면의 도킹 직선에서 옆 오차 12cm·최종 위치 전방 거리 75cm 이내이면 `docking_handoff`로 전환한다. 자신의 Nav2 목표만 취소하고 액션 종료와 실제 정지 0.4초를 확인한 뒤 현재 위치를 다시 판정한다. 이때부터 Nav2의 상판 XY 투영·inflation·Spin/BackUp 판정 대신 기존 실제 3D 형상 보호 아래 최대 0.06m/s로 도킹한다. 반대편 책상을 가로질러 전환하지 않으며, 추정만 한 면에서는 정지 이후 새 LiDAR 경계 관측이 필요하다. 복구를 위해 준비 위치로 되돌아가는 강제 Nav2 이동은 도킹 직선 안이라는 이유만으로 취소하지 않는다. 실제 몸체·팔 형상과 3D guard/watchdog은 유지한다.

3D 물체 위치 추정과 책상 면 추정은 서로 다른 작업이다. `head_lidar.locate`는 책상 추정 결과 없이 물체 좌표를 반환한다. 책상 추정은 이동 중 전용 worker에서 수행하며 물체 좌표 융합 worker와 분리한다. 책상 추정이 오래 걸리거나 실패해도 YOLO/LiDAR 좌표 처리를 기다리게 하지 않는다. 책상 모델이 없는 동안에는 저장 물체 좌표 쪽 접근을 계속한다. 물체 좌표 2cm 이내로 정렬하거나, 물체 전방 도달 범위 안에서 실제 몸체 충돌 보호가 더 이상 전진을 허용하지 않으면 `at_target`으로 물체 앞 도착을 표시한다. 이 상태는 정밀 파지 위치 확정이나 팔 파지 완료와 구분한다. 책상 접근 후보를 못 만들면 기존 좌표 접근과 실제 3D 보호를 유지하며 재관측한다. 책상 모델의 실패만으로 기존 주행을 먼저 취소하지 않는다. 정밀 이동·방향 정렬이 3초간 진행하지 못하면 아래 직선 후진 복구로 전환한다.

YOLO JSON·CameraInfo·LiDAR·오도메트리와 TF는 **별도 `inha_detection_inputs` ROS 노드와 단일 executor 스레드**로 받는다. 관제 영상 JPEG·점군 시각화·HTTP 처리와 같은 executor를 사용하지 않는다. 별도 스레드에서 웹 노드를 다시 spin하는 방식도 사용하지 않는다. 점군 변환은 이 입력 노드의 20Hz 타이머에서 처리하고, 촬영 시각의 TF를 정확히 사용한다. 처리 지연을 감추려고 최신 TF로 바꾸거나 관측 시각을 새로 쓰지 않는다. 책상 점군 한 프레임의 TF 대기가 물체 점군 처리를 막지 않도록 재시도 프레임을 뒤로 보내며, odom/시각 초기화에서는 epoch가 다른 변환 결과를 버린다. 물체 현재 상대 위치와 정지 확인도 이 입력 노드의 TF·오도메트리를 사용한다.

도킹용 모델 관절 피드백도 같은 독립 입력 노드에서 받는다. 원본 odometry 위치·yaw·측정 시각으로 실제 프레임 점프를 추적하며, 웹 콜백이 0.5초 늦었다는 이유만으로 좌표를 지우지 않는다. 현재 odometry 수신 시각과 실제 3D guard의 입력·출력 만료는 계속 적용한다. 실제 원본 위치 점프나 ROS 시각 역행에서는 저장 좌표를 무효화한다.

`detection_control.inputs`에는 YOLO·LiDAR·CameraInfo·오도메트리 수신 수와 원본 시각 지연, 변환된 점군 수, TF 재시도·만료·입력 오류를 표시한다. 관측 중에도 이동 요청이 없으면 관측 상태로 명시하며, 이동 중에는 YOLO 영상 접근·LiDAR 좌표 확보·근접 제어 전환 단계를 표시한다. `position_note`는 물체 박스의 LiDAR 군집 점 수와 좌표 처리 사유를, `visual_target`은 영상 박스와 차체 기준 방향을 제공한다.

일반 NAV·물체 XY 이동·책상 준비 위치 이동에는 전방 장애물용 `front_retreat`를 적용한다. 실제 3D 보호의 전방 차단이 0.15초 유지되면 자신의 Nav2 목표를 취소하고 정지를 확인한 뒤 기본 8cm를 최대 0.05m/s로 후진한다. 후방 궤적도 기존 3D guard가 검사한다. 정밀 도킹의 `docking_handoff`, `settling`, `observing_table`, `aligning`, `approaching`, `final_align` 및 자체 복구 단계에서는 이 후진과 경로 제외가 개입하지 않는다.

정밀 도킹은 자체 제어기가 완료 조건과 15cm 직선 후진 복구를 소유한다. `front_retreat.distance`는 일반 Nav2/물체 좌표 접근용 설정이며 정밀 도킹 복구 거리에는 적용하지 않는다.

짧은 후진은 같은 정체 구간에서 최대 2회, 시도 사이 3초 간격으로 제한한다. 후진 후 이전 차단 자세의 25cm·yaw 0.5rad 이내에서 다시 막히면 이 간격을 기다리지 않고 추가 후진을 생략해 다른 경로를 선택한다. 마지막 후진 정지 위치에서 15cm 이상 이동하거나 사용자가 새 목표를 요청하면 후진 횟수를 다시 사용할 수 있다. 회전만 반복하는 것은 횟수를 초기화하지 않는다. Nav2와 도킹이 후진 중 속도 명령을 함께 발행하지 않으며, 사용자 취소·목표 교체·관제센터 종료에서는 후진을 멈추고 목표를 자동 복원하지 않는다. 3D 보호·actuator·오도메트리 입력 지연에는 정지한 채 최대 3초 기다렸다가 이어간다. 실제 오도메트리 불연속·3초 초과 입력 지연·정지 확인 실패는 중지 사유다. 보호 상태는 화면 처리와 별개의 ROS 입력 스레드에서 직접 수신한다. `navigation.front_retreat`에 진행 상태·원인·요청/실제 거리를 표시하고, Detection에서는 접근 단계와 `reverse_assessment`에도 기록한다.

후진 차단·유효 진행 없음·같은 진입 재차단은 `rerouting_obstacle`로 전환한다. 차체 정지 후 `/navigation/blocked_routes`로 실패한 odom 자세를 보내고 global costmap의 `RouteAvoidanceLayer`가 그 앞 15~55cm·좌우 30cm 구간을 30초간 경로 계획에서 제외한다. Nav2의 2Hz 재계획과 costmap 초기화에도 이 제외는 남아 같은 직진 경로를 그대로 고르지 않게 한다. 제외는 global costmap에만 적용하며 실제 LiDAR 점군·3D 몸체 판정·local 회전 충돌 모델은 유지한다. 반영을 위해 0.5초 정지한 뒤 새 목표를 보낸다. Detection은 실패한 책상 면을 이번 요청의 후보에서 제외하고 다른 파지 가능 면을 먼저 선택한다. 다른 면이 없으면 기존 면으로 가는 별도 우회로를 탐색한다. 같은 정체에서 대체 경로 전환도 최대 3회로 제한하고 소진되면 정지한다. 새 요청·취소·종료·일반 Nav2 목표 종료에는 제외를 지우며, 별도 메시지가 없어도 30초 후 소멸한다. 이 제약을 만족하는 우회로가 없으면 Nav2의 제한된 복구 후 실패를 표시하며 정지한다.

DWB 최소 x 속도는 0m/s로 두어 평상시 경로 추종 후보에서 후진을 제외한다. 전방 짧은 후진 조건이 없거나 같은 정체의 시도를 소진했을 때는 기존 BT 복구를 사용한다. `PoseProgressChecker`는 5cm 이동 또는 0.10rad 회전을 진행으로 인정하고, 6초간 둘 다 없으면 복구를 시작한다. 세 BT의 이동 복구는 `Fallback` 안에서 왼쪽 45° 회전 → 오른쪽 45° 회전 → 8cm 후진(0.05m/s) 순서로 시도한다. 회전 하나가 성공하면 재계획하며, 두 회전이 모두 실패하면 BT 후진에 진입한다. costmap 갱신·1초 대기도 제한된 복구에 포함한다. 각 동작의 허용 시간은 6초, BT 재시도는 최대 6회다. 회전에는 Nav2 costmap 검사를 유지한다. BT의 BackUp은 `robocup_collision_processing::GuardedBackUp`을 사용한다. 출발 자세의 2D 외곽 겹침만으로 후진을 거부하지 않고, 실제 후진 궤적은 기존 3D guard와 actuator watchdog이 검사한다. 후진 거리는 오도메트리로 측정하며 입력이 일시 지연되면 정지한 채 최대 3초 기다린다. 실제 3D 후진 차단 시 로봇 부위와 차단점 좌표를 기록한다. 후보를 모두 소진하면 도달 범위 안인 다른 책상 면으로 다시 계획한다.

세 BT 모두 전체 재시도가 소진되면 곧바로 실패하지 않고 `FinalReverseAssessment` 분기로 들어간다. BackUp이 8cm·0.05m/s·6초 제한으로 후진 가능 여부를 검사하고, 성공하면 현재 목표로 경로 계획·추종을 한 번 더 수행한다. 기존 취소는 트리를 halt하므로 이 분기로 진입하지 않는다. `/backup/_action/status`를 현재 Nav2 목표의 시작 시각으로 필터링해 `navigation.reverse_assessment`와 관제 로그에 시작·실행·성공·취소·실패를 남긴다. 늦게 도착한 최종 결과도 실패 메시지에 반영한다.

마지막 정밀 접근은 Nav2 종료와 실제 정지를 확인한 뒤 시작한다. 3초간 정밀 이동·정렬에 진전이 없거나 도킹 옆 오차가 남으면 `recovering`으로 전환한다. 현재 방향을 유지한 채 최대 15cm를 0.05m/s 이하로 직선 후진하고, 정지 후 Nav2 준비 위치로 재접근한다. 책상 바로 앞에서 좌우 45° 회전을 시도하지 않는다. 후진 중 옆 이탈 3cm·yaw 이탈 0.10rad를 넘거나 1.2초간 진행이 없으면 중지한다. 5cm 이상 이동한 뒤 막히면 확보한 공간에서 재계획할 수 있다. 후진 시간은 최대 8초, 정밀 복구는 요청당 최대 2회이며 모든 명령은 기존 3D guard와 watchdog을 통과한다.

Detection은 Nav2 최종 실패·정밀 복구 2회 소진·기본 접근 시간 초과·책상 접근 면 계획 시간 초과에 `checking_reverse`로 전환한다. 기본 복구를 소진했을 때 요청당 한 번 수행하는 최종 후진 판단이다. 자신의 기존 Nav2 목표만 취소하고, Nav2 종료와 실제 차체 정지를 최대 10초 확인한다. 이후 오도메트리·3D 보호 입력이 준비된 상태에서 `final_reverse`로 전환해 기존 guard가 후진 궤적을 검사하도록 한다. 일반 접근과 최종 방향 정렬 모두 최대 15cm·0.05m/s·동작 8초 제한을 사용한다. 실제 후진 거리는 오도메트리로 확인하고, 움직였으면 기존 목표로 재접근한다. 후진 판단과 한 번의 재접근을 위해 기존 제한 시각에서 최대 40초의 동작 여유를 주며, 앞선 정지 확인을 포함한 추가 시간은 최대 50초다. 다시 실패하면 최종 후진을 반복하지 않는다.

`detection_control.reverse_assessment`와 로그에 `waiting`·`checking`·`moved`·`blocked`·`no_progress`·`unavailable`, 실제 이동 거리와 차단 사유를 기록한다. 센서·오도메트리·정지 상태를 확인할 수 없는 오류는 후진 불가 사유를 남기고 중지한다. 사용자 취소·목표 교체·서버 종료에는 자동 후진하지 않는다. Nav2의 2D 판단과 별도로 도킹의 마지막 후진은 기존 3D guard·watchdog을 통과하며, 최종 충돌 모델은 축소하지 않는다.

일반 주행·책상 우회 경로는 통로 중앙을 선호하도록 local/global inflation 반경 1.50m, 비용 감쇠 계수 2.0의 완만한 비용 구배를 사용한다. `prepare-navigation-profile.py`가 이 범위를 몸체 내접 반경으로 줄이지 않도록 하고, 선택된 별도 프로필도 최소 반경 1.50m·최대 감쇠 계수 2.0을 적용한다. 실제 몸체 외곽과 추가 충돌 여유 0cm는 유지한다. `FollowPath`의 `BaseObstacle.scale`은 0.03, 책상 준비 위치용 `GraspApproach`는 0.01로 두어 비용 구배가 지정 목표 도착 자체를 밀어내지 않게 한다. 마지막 정밀 접근의 `/cmd_vel` 제어와 3D 보호는 기존 방식이다. 장애물이 비대칭이거나 통로가 매우 넓으면 경로가 정확한 기하학적 중앙선과 일치하지 않을 수 있다.

실패 시 DWB 충돌·진행 불가 등 수신한 원인을 함께 표시한다. inflation 반경의 최솟값은 float32 외곽 전송 반올림을 고려한 몸체 내접 반경 이상으로 유지한다.

## 책상 가장자리와 파지 위치

파지 완료에는 선택한 책상 면과 현재 로봇 형상 사이의 상대 간격, 도킹 축 방향 오차, 측면 오차와 방향 오차를 함께 요구한다. `grasp_table_gap_limit`의 기본값과 실물 프로필은 0.03m이고 허용 설정 범위도 0~0.03m다. 과거 0.269088208159348m 값은 더 이상 사용하지 않는다. 상대 간격이 음수인 자세는 완료로 인정하지 않는다.

마지막 목표 15cm 구간은 최대 0.02m/s로 접근한다. 완료에는 축 방향 오차 1.5cm 이내·측면 오차 2cm 이내·책상 법선 방향 오차 2° 이내와 상대 간격 0~3cm가 모두 필요하다. 최종 정렬 중에도 위치·간격을 다시 확인하고 선속도 0.01m/s·각속도 0.02rad/s 이하를 0.6초 유지해야 `succeeded`로 인계한다. 충돌 가드의 차단만으로 완료하거나 10cm 위치 허용으로 정밀 제어를 건너뛰지 않는다. 책상 미확인 `at_target`은 정밀 도킹 성공과 구분한다.

`head_lidar.py`는 물체 위치용 `/mid360/points_obstacles`와 책상 경계용 `/mid360/points_filtered`를 각 측정 시각에 `odom`으로 변환한다. 경계용 점군에는 바닥에 맞은 광선도 포함해, 상판 스캔이 단순히 가림으로 끊긴 곳과 실제 가장자리를 구분한다.

`grasp_approach.py`는 기존 `surface_geometry`의 수평 면·광선 경계 추정을 재사용한다. 물체 아래 상판의 각 면에서 파지 도달 거리를 계산해, 가까운 면에서 닿지 않으면 옆면·반대편 준비 위치를 선택한다. 경계 관측 비율 0.4 미만인 면도 우회 준비 위치 후보로 사용하지만 정밀 접근에는 사용하지 않는다. 이 경우 도착 이후의 LiDAR로 같은 방향의 실제 경계가 0.4 이상 관측되어야 파지 위치를 확정한다. 15초 안에 확인되지 않으면 정지하고 이유를 표시한다. 카메라가 물체를 계속 볼 필요는 없다.

현재 팔 실측 관절을 적용한 공용 `RobotGeometry`의 OBB를 상판 아래 `table_body_depth`(기본 0.12m)부터 상판 위 5mm까지의 구간과 교차시켜 최소 가장자리 거리를 계산한다. 상판과 에이프런을 함께 고려하고, 다리·의자 등 전체 3D 장애물은 기존 충돌 보호가 계속 검사한다. 실제 책상 두께에 맞춰 깊이를 설정할 수 있으며 0.04~0.30m 범위를 허용한다.

파지 yaw는 선택한 책상 면의 안쪽 법선으로 고정한다. 물체가 차체 기준 선호 좌표 `(x=0.392m, y=-0.078m)`에 가까워지도록 측면 위치와 후보 비용을 계산한다. 이는 후보 배치 기준이며 실물 IK 성공을 보장하는 도달성 지도는 아니다. 물체가 전방 도달 범위(기본 0.50m)를 벗어나거나 면 끝에서 필요한 측면 배치를 만들 수 없으면 해당 후보를 제외한다. Nav2 준비 거리는 가장자리에서 차체 중심까지 기본 0.65m이며 최종 방향과 같은 도킹 선 위에 놓인다.

최종 정렬이 3초간 진행되지 않아도 동일한 직선 후진 복구를 사용한다. 후진 후에는 Nav2 준비 위치에서 다시 실측 경계를 확보해 접근한다. 충돌 보호를 우회하거나 방향이 맞지 않은 자세를 완료로 보고하지 않는다.

일반 NAV도 `StoppedGoalChecker`로 위치 5cm·yaw 0.02rad 이내와 실제 정지를 함께 확인한다. Nav2 footprint는 모든 실제 형상 꼭짓점을 포함하는 볼록 다각형으로 생성·갱신해 직사각형의 빈 모서리를 줄인다. 3D guard의 실제 차체·팔 크기와 추가 이격 0cm 설정은 유지한다.

## 카메라에서 사라진 뒤

YOLO 촬영 시각의 optical 프레임에 최근 최대 2초의 odom LiDAR 관측을 K/D로 투영한다. 최근 스캔의 기존 신선도 조건도 유지한다. 왜곡을 포함해 투영한 픽셀을 다시 광선으로 역변환하고 원래 3D 점의 광선과 2픽셀 상당 오차 이내로 일치하는지 검사한다. 왜곡 다항식이 실제 시야 밖의 옆면 점을 영상 안으로 접어 넣는 가짜 투영은 제외한다. 작은 박스의 중앙 영역에 점이 부족하면 박스 내부에서만 관측 영역을 넓혀 군집을 찾는다. 대표 위치는 가까운 군집 안 실제 LiDAR 점이며 RGB-D 깊이로 바꾸지 않는다. 촬영 시각, LiDAR 시각, 물체 점·책상 경계·차체 목표를 `odom`에 저장한다. 처음 연결할 물체 박스는 Head YOLO의 영상 위치와 신뢰도로 고르며 LiDAR 거리로 다른 박스를 선택하지 않는다. 새 요청의 영상 선택 이후 촬영한 검출이고 카메라 광선 일치가 확인된 좌표만 현재 요청의 기준점으로 확정한다. 이 기준점을 확정한 뒤에는 고정한다. 물체가 카메라 시야에서 사라져도 현재 오도메트리로 남은 위치와 물체 방향을 계산해 계속 접근한다. SLAM 보정은 지도 표시와 Nav2 준비 목표 변환에만 반영한다.

새 이동 요청에서는 이전 요청·대기 상태의 좌표와 처리 중인 융합 결과를 지우고, 요청 이후 촬영한 Head YOLO 검출에서 물체를 다시 선택한다. LiDAR 좌표만으로 출발하거나 같은 이름의 과거 좌표로 바로 전환하지 않는다. 처음 LiDAR 좌표를 연결하기 전에는 현재 요청에서 YOLO 영상 추적이 먼저 성립해야 한다. 좌표가 없으면 YOLO 물체 발견을 최대 30초 기다린 뒤 영상 기반 접근을 시작한다. 영상 접근 중 YOLO가 끊기면 즉시 0속도를 발행하고 최대 3초 재관측한다. 이미 저장한 3D 좌표로 전환한 뒤에는 카메라 시야 이탈로 접근을 취소하지 않는다. 기본 접근 제한은 120초이며, 실패 전 최종 후진 판단·재접근에만 위의 최대 50초 추가 여유를 사용한다. ROS 시각·오도메트리가 불연속이면 좌표를 버리고 다시 관측한다. 시야 밖에서 물체가 옮겨졌다면 저장 좌표 지우기로 다시 선택한다. 목표 기억과 현재 장애물 판단은 별개다. `/cmd_vel → 3D guard → actuator watchdog → Tracer` 경로와 몸체 기준 추가 충돌 여유 0cm를 유지한다.

## 설정과 인터페이스

`config.json` / `config.example.json`의 detection 설정:

- `objects_topic`, `odom_topic`, `cloud_topic`, `surface_topic`, `camera_info_topic`: YOLO JSON·오도메트리·물체·책상·원본 RGB 내부 보정 입력.
- `table_clearance`: 기본 추가 이격 0m, UI 설정 0~0.1m.
- `stage_edge_distance`: Nav2 준비 위치의 가장자리 거리, 기본 0.65m.
- `grasp_max_forward`: 물체 전방 도달 범위, 기본 0.50m. 실제 파지 가능성은 후속 실물 IK에서 판단한다.
- `grasp_table_gap_limit`: 완료 허용 최대 상대 간격. 기본 0.03m, 허용 0~0.03m.
- `grasp_preferred_x`, `grasp_preferred_y`: 도킹 후보의 선호 물체 좌표. 기본 0.392m, -0.078m.
- `table_body_depth`: 상판/에이프런을 고려하는 높이 구간 깊이. 기본 0.12m.

공통 `front_retreat.distance`는 NAV·Detection이 공유하는 전방 장애물 후진 거리다. 기본 0.08m이며 0.05~0.10m로 설정할 수 있다. 도킹의 추가 이격이나 최종 도착 거리와는 별개다.

`POST /api/detection`은 start/stop/select(label)/find_and_approach(label, edge_clearance)/approach(edge_clearance)/cancel/clear를 지원한다. `select`는 관측 대상을 고르는 기존 인터페이스이며, 화면의 찾아서 이동은 `find_and_approach`로 이름 적용과 이동 예약을 함께 처리한다. HTTP 202는 접수이며 실제 결과는 SSE detection_control에 표시한다. 이전 distance 필드를 보낸 화면에는 새로고침 안내를 반환한다.

`detection_control`과 `/detection/closed_approach/status`에는 Nav2 활성화·책상 계획·방향 정렬·정밀 접근 상태, 저장 목표와 촬영 시각, 책상과 파지 목표가 포함된다. `/detection/closed_approach/target`은 실제 촬영 시각과 odom 좌표를 보존한다.

관제센터와 Nav2를 재시작해야 새 코드와 GraspApproach 컨트롤러가 반영된다. 실행 중 지도는 먼저 pose graph로 저장하고 `--mapping --resume-mapping-params <profile.yaml>`로 이어 읽을 수 있다. 복원 프로필은 최초 SLAM 시작에만 사용하고, 이후 화면의 초기화는 기본 프로필로 새 지도를 시작한다. 이전 이동·접근 명령을 자동으로 재실행하지 않는다.

대기·취소 상태에서는 현재 YOLO에 없는 물체의 과거 점을 새 관측처럼 표시하지 않는다. `target.visible`은 현재 YOLO 검출 여부이며 LiDAR 점 갱신 시각을 가시성으로 사용하지 않는다. 현재 요청에서 이미 확정한 목표는 시야 밖에서도 저장 좌표로 계속 표시·접근한다. `selection_source=head_yolo`, `projection_verified`로 좌표 연결 근거를 제공하며, `inputs.projection_off_ray_rejected`는 영상 밖 광선의 잘못된 투영으로 제외한 점 수다.

현재 요청의 도킹 완료는 `accepted_position` 조기 종료를 사용하지 않는다. `position_tolerance`는 0.015m이고 측면·방향·상대 간격 조건을 별도로 적용한다. 책상 모델이 없는 물체 좌표 접근은 2cm 이내 또는 물리적 몸체 한계에서 `at_target`으로만 종료한다.

Detection의 센서↔odom 변환은 수신한 `/odom_ekf`의 측정 시각별 자세 이력과 센서 외부 보정 TF를 합성합니다. 같은 EKF가 발행한 `/tf`가 입력 executor에서 늦게 처리됐다는 이유만으로 정상 점군을 버리지 않습니다. 오도메트리는 200개 수신 queue와 200개 자세 이력으로 보존하며 점군·영상의 원래 측정 시각 양쪽 자세 사이에서 보간합니다. 80ms보다 큰 원본 자세 공백·현재 odom 지연·프레임 초기화에서는 변환을 거부하고, 최신 자세로 대체하거나 외삽하지 않습니다. `inputs.pose_transform_source=timestamped_ekf_odometry`와 `pose_history_frames`로 변환 근거를 표시합니다. 지도↔odom 보정은 기존 TF 경로를 유지합니다.

## 독립 제어 프로세스와 실시간 경계 추적

`ros_bridge.py`는 `control_process.py`를 통해 `inha_docking_control` 프로세스를 시작한다. `navigation_controller.py`가 Nav2 액션·짧은 후진·20Hz `DetectionApproach`를 소유한다. 웹의 JPEG·지도 PNG 인코딩과 Python GIL을 공유하지 않는다. 웹 상태는 5Hz, Nav2 상태는 10Hz로 전달하며 상태 큐에는 채널별 최신 값만 보관한다. 관제 연결이 1.5초 이상 끊기면 진행 중 이동을 취소하고 0속도를 보낸다. 프로세스가 재시작되어도 이전 이동 명령을 재생하지 않는다.

정밀 도킹 진입 시 `/mid360/points_filtered`의 최근 0.25초 점군을 취득 시각별로 odom에 정렬하고, 최신 스캔 시각의 차체 좌표로 바꿔 `fit_edge()`에 전달한다. 선택한 면의 거리 8cm·법선 6° 이내인 피팅만 목표에 반영한다. 다른 책상이나 물체 그림자에 맞춘 선으로 목표를 바꾸지 않는다. 거리·각도 보정에는 완만한 필터를 적용하고 같은 면의 목표와 상대 간격을 다시 계산한다.

예상 경계가 MID-360 사각 한계보다 10cm 앞에 도달하면 마지막으로 확인한 경계를 고정하고 오도메트리로 마무리한다. 실측 피팅을 한 번도 확보하지 못한 채 사각 구간으로 들어가면 완료하지 않으며, 관측이 끊기면 정지한 뒤 최대 3초 기다리고 직선 후진 복구로 전환한다. `detection_control.edge_tracking`에는 `waiting`/`tracked`/`frozen`과 마지막 실측 시각이 들어간다. `controller_process`는 제어 프로세스 PID, `control_hz=20`은 설정 주기다.

변경 사항은 저장소 소스 기준이다. 실행 중인 관제센터와 설치된 manipulation overlay는 자동 교체하거나 재시작하지 않는다. Phase 2의 동적 MoveIt 장면·궤적 보간 및 Phase 3의 영상/TensorRT 최적화는 후속 범위다.


## Phase 2·3 추가 연결

도킹 성공 시 `/detection/dock/surface`에 odom 테이블 polygon과 완료 시각을 발행한다. 접근 진행/취소/오류 단계에서는 빈 polygon으로 이전 인계를 무효화한다. 매니퓰레이션의 시간 대응·좌표 변환·작업별 고정 계약은 [MANIPULATION.md](MANIPULATION.md)를 따른다.

Head RGB 입력은 `/head/camera/color/image_raw`이며 실측 내부 보정은 `/head/calibrated/color/camera_info`다. calibrated_streams는 CameraInfo만 발행한다. Wrist 원본 RGB는 `/wrist/wrist/color/image_raw`다. 기존 `/head/calibrated/color/image_raw`, `/wrist/calibrated/color/image_raw` 중계 토픽은 더 이상 발행하지 않는다.

`HeadLidar.locate`는 보정값별 캐시된 optical ray 경계로 3D frustum을 먼저 검사한 뒤 남은 점만 OpenCV에 투영한다. 왜곡을 반영한 여유 경계를 사용하며 기존 image bounds·광선 역투영 일치 검사를 유지한다. diagnostics의 `projection_input_points`, `projection_frustum_points`, `projection_ms`로 후보 감소와 투영 비용을 확인할 수 있다. 이는 실행 시 계측값이며 소스 변경만으로 성능 달성을 주장하지 않는다.
