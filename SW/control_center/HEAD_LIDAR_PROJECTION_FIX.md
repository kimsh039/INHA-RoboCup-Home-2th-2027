# YOLO 박스에 시야 밖 LiDAR 점이 연관되는 문제

2026-10-16 Jetson의 실제 컵 관측에서 재현했다. Head YOLO는 약26FPS로 검출하고 있었으나, 컵으로 선택된 LiDAR 좌표의 방향은 영상 방향과 크게 달랐다.

- `CameraInfo`: 640×480, `plumb_bob`, K=`[605.53244,0,331.95871,0,608.06854,243.32325,0,0,1]`, D=`[0.082175,-0.163474,-0.001177,0.005889,0]`.
- 당시 컵 박스: x≈395.9..419.7, y≈243.8..268.3.
- 잘못 선택된 실제 LiDAR 점을 광학좌표로 변환하면 `(1.977014,0.512434,1.249595)m`.
- 이상적인 pinhole 투영은 `(1289.99,492.68)`로 영상 밖인데, 범위 밖에서 Brown 왜곡 다항식을 적용하면 `(409.19,259.03)`으로 접혀 컵 박스 안에 들어온다.
- 기존 코드는 유한한 점과 양의 Z만 확인한 뒤 왜곡 투영 결과로 박스 연관을 판단했다. `3회 확인`도 같은 잘못된 투영을 반복하면 통과할 수 있다.

`head_projection.camera_ray_mask`는 실제 센서 경계 픽셀을 역왜곡해 정규화 광선의 범위를 구하고, 그 범위 밖의 LiDAR 점을 왜곡 투영 전에 제외한다. 이후의 왜곡 보정·YOLO 박스 검사·실측 LiDAR 깊이 사용은 유지한다. 보정 K/D, TF, 검출 모델, 점군 시각/개수 조건은 변경하지 않는다. 경계 계산 캐시는 최대8개로 제한한다.

검증:

```bash
python3 -m unittest discover -s SW/control_center/tests -p test_head_projection.py -v
```

실제 오검출 점의 배제, 센서 전체 영역의 정상 광선 보존, 비정상/뒤쪽/시야 밖 점 배제3개가 통과했다. 테스트는 원본 수치의 계산 재현이며 실물 자동 접근 성공 검증이 아니다.

이 수정은 로컬 소스와 브랜치에 준비했다. 점검 당시 Jetson에서 자동 접근이 진행 중이어서 실행 중인 관제센터를 교체하거나 재시작하지 않았다. 배포 시 Jetson의 최신 `head_lidar.py`를 파일 전체로 덮지 말고, `head_projection.py` 추가 및 import/visibility-mask 두 삽입만 적용해야 다른 작업자의 최근 영상 접근 수정이 보존된다. 원본 백업과 해시 확인 후 재시작이 필요하며 과거의 잘못 연관된 목표는 새 좌표 검증 전 재사용하지 않는다.
