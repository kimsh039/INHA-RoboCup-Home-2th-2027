# PiPER 연결 진단 — 2026-10-15

## 확인한 실행 상태

- USB CAN serial `004E00235246571520393733` → `can_arm`; 커널 드라이버 `gs_usb`.
- CAN 1,000,000 bit/s, `ERROR-ACTIVE`. Tracer는 다른 serial과 별도 500,000 bit/s 버스다.
- 진단 시작 때 관제센터와 PiPER ROS 프로세스는 실행되지 않았다.
- 수신 필터 없이 관측해도 팔 버스에 주기 프레임이 없었다. 다른 버스에는 Tracer 프레임이 있었다.
- 펌웨어 조회 `0x4AF#0100000000000000`에는 11개 응답 프레임을 받았다. 소프트웨어 버전은 `S-V1.6-5`다. 따라서 그 시점에 USB CAN과 팔 컨트롤러 사이의 왕복 통신은 가능했다.
- 설치된 공식 SDK 0.6.2의 `ConnectPort()`로도 펌웨어는 읽혔으나 관절, 상태, 모터 제한 응답의 타임스탬프는 0이었다. SDK의 각도 0과 `NORMAL` 표시는 수신한 상태가 아니라 초기 기본값이었다.

## 복구 조치와 관측

제조사 `MasterSlaveConfig(0xFC, 0, 0, 0)`에 해당하는 `0x470#FC00000000000000`을 한 번 전송했다. 이 직후 3초 동안 관절 프레임은 없었다. 이후 사용자가 팔 본체 전원을 완전히 껐다가 다시 켰다. 재전원 후 3초 관측에서 다음 데이터가 들어왔다.

| 종류 | CAN ID | 관측 |
|---|---|---|
| 관절 1–6 | `0x2A5`, `0x2A6`, `0x2A7` | 각각 600개/3초, 약 200 Hz |
| 팔 상태·끝단·그리퍼 | `0x2A1`–`0x2A4`, `0x2A8` | 각각 약 200 Hz |
| 6개 모터 고속 정보 | `0x251`–`0x256` | 각각 약 200 Hz |
| 6개 모터 저속 정보 | `0x261`–`0x266` | 각각 약 40 Hz |

관측 시 CAN 오류 카운터는 0이었다. 진단 중 모터 enable/disable, 이동, 원점 복귀, 영점 설정 명령은 전송하지 않았다. 단, 제조사 주종 모드 변경 자체가 팔 모터를 비활성화할 수 있으므로 이를 주기적인 자동 복구 명령으로 넣지 않는다.

관제센터를 시작한 뒤 ROS 수신 경로에서도 `/piper/joint_states_feedback`과 `/robot/joint_states`가 약 200 Hz로 발행됐다. 관측한 헤더 시각 지연은 각각 약 4 ms와 9 ms였고 `/piper/feedback_status`는 `live`, 누락 프레임은 없었다. 임시 진단 실행을 종료하고 `inha_control_center` tmux 세션으로 다시 시작했다. 관제센터 API에서도 PiPER 관절 상태 `live`, 관절 퍼블리셔 1개, `can_arm` 실시간 수신을 확인했다.

이때 충돌 보호 입력도 `ready: true`가 되어 `stale_arm_feedback` 차단은 해소됐다. 다만 보호 출력은 `clearance_boundary`로 정지 상태였다. 가장 가까운 점이 랙 링크에 거리 0으로 잡혔으므로, PiPER 연결 복구를 실제 주행 가능 판정과 동일하게 취급하지 않는다. 이 진단에서는 차체를 이동하거나 해당 보호를 해제하지 않았다.

## 판단과 남은 불확실성

이번 장애는 컨트롤러가 펌웨어 요청에는 응답하면서 주기적인 관절/상태 피드백을 내보내지 않는 상태였다. 드라이버 미설치나 ROS 토픽 이름 오류만으로 설명되지 않는다. slave 설정 후 재전원으로 복구했으나 설정 변경과 재전원의 효과를 따로 실험하지 않았으므로 원래 master 모드였다고 확정하지 않는다. MCU의 내부 정지 원인, 전원 안정성 또는 펌웨어 결함 여부도 이번 관측만으로 확정할 수 없다.

공식 문서는 관절 피드백에 slave 모드가 필요하다고 설명한다. 상위 버전 펌웨어의 주종 상태 관련 장애 보고는 있으나 이 팔의 `S-V1.6-5`에 같은 결함이 있다고 단정하거나 펌웨어를 임의로 교체하지 않았다.

수신 노드는 실제 `0x2A5/6/7`과 커널 수신 시각으로만 관절을 발행한다. 프레임이 끊기면 기본 각도를 발행하지 않고 기다리며 재연결한다. 관제센터는 `/piper/feedback_status`를 별도 표시해 CAN 인터페이스 준비와 실제 6관절 수신을 구분한다. 자동 slave 전환, 모터 활성화 또는 재시작 명령은 추가하지 않는다.
