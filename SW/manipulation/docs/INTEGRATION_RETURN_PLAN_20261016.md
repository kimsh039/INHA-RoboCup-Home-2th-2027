## 최우선 동작 계약

도킹 후 이동은 반드시 다음 순서를 따른다.

`지정 홈 확인 → closed approach → 도킹 유지 → [팔 작업 → 팔 주행 자세 복귀] → 이탈 준비 → 직선 후진 → 실측 정지 → 제자리 회전 → Head 진행 방향 정렬·실측 정지 → Nav2 홈 복귀 → 홈 도착·정지`

- 팔을 사용하는 작업은 정상 놓기·주행 자세 복귀가 확인된 뒤 이탈한다. 도킹만 확인하는 모드에서는 팔의 현재 주행 자세·정지를 확인하고 같은 이탈 경로를 쓴다.
- 복귀 목적지는 사용자 선택에 따라 **미리 지정한 홈 위치·방향**으로 확정한다. 접근 시작 위치로 자동 대체하지 않는다.
- 관제센터에서 홈의 map 좌표 `(x, y, yaw)`와 지도 ID를 저장한다. 현재 위치를 홈으로 등록하는 명시적 동작도 제공한다. 등록 시각·설정 버전을 함께 보존하고 작업 시작 시 해당 홈 설정을 작업 문맥에 고정한다. 도킹 중 목표 재계획·표면 갱신으로 덮어쓰지 않는다.
- 홈 미설정·지도 불일치·홈까지 경로 없음이면 자동 복귀를 시작하지 않고 도킹 잠금을 유지한다. 현장 홈 좌표는 아직 지정되지 않았으므로 임의 좌표를 넣지 않는다. 작업 중 홈 설정 변경은 정지 후 명시적인 목적지 갱신 요청으로만 반영한다.
- 기본 복귀 경로는 새로 계획한다. 들어온 경로를 시간 역순으로 재생하거나 전체 거리를 뒤로 주행하지 않는다.
- Head는 현재 고정 장착 구조다. 차체 회전과 실제 base→Head optical TF로 수평 시선 방향을 계산한다. 별도 Head pan/tilt 구동기를 전제하지 않는다.
- 우회가 필요할 수 있으므로 정렬 목표는 목적지 직선 방위가 아니라 **충돌 없는 복귀 경로의 첫 유효 전진 구간 방향**이다. 카메라 장착 yaw 오프셋을 반영하고, 차체 진행 방향과 Head 시야가 함께 만족하는 범위를 사용한다.

## P0 — 도킹 후 이탈·복귀 순서 강제 (첫 구현)

### 1. 지속되는 도킹 상태와 이동 소유권

- 새 `DockDeparture` 상태 머신을 독립 `NavigationController` 안에 둔다. 웹은 요청과 상태 표시만 담당한다.
- 도킹 완료 시 작업 ID, 완료 pose/odom epoch, 실측 책상 polygon, 접근 면의 법선, 복귀 목적지, 지도 ID, 팔 상태를 보존한다.
- `docked`는 성공 UI 문자열이나 active=false와 별개로 유지한다. 취소·목표 교체·웹 재시작만으로 이탈 완료로 간주하지 않는다.
- 도킹 뒤 일반 NAV 목표, Detection 재접근, 복귀 버튼 모두 동일 이탈 진입점을 거친다. 대기 중 목적지는 하나만 소유하고, 실행 중 교체는 정지 후 재계획한다.
- Nav2·기존 FrontRetreat·도킹·이탈 간 속도 소유권을 배타적으로 관리한다. 도킹 근처에서는 Nav2 recovery spin이나 일반 FrontRetreat가 별도로 끼어들지 않는다.
- 최종 Tracer 출력 경로에도 이탈 단계와 허용 명령을 연결한다. 웹 경로만 제한하고 다른 cmd_vel 소유자가 순서를 우회하는 구조를 만들지 않는다.
- 프로세스 재시작·지도 교체·odom reset 뒤에는 자동 재출발하지 않는다. 저장한 도킹 문맥을 유지하되 센서·좌표계·팔 상태를 다시 확인해야 한다.

### 2. 상태별 전이 조건

| 단계 | 허용 동작 | 다음 단계 조건 |
|---|---|---|
| DOCKED_HOLD | 정지, 팔 작업 | 복귀/다음 이동 요청 및 팔 작업 종료 |
| PREPARE_DEPARTURE | 정지, 경로 계산 | 신선한 TF·odom·점군·관절 피드백, 팔 주행 자세, 경로 존재, 기존 action 종료 |
| TRANSFER_BASE_CONTROL | 정지 | 동일 작업 ID로 잠금 소유권 전환, 새로운 ACK, 이탈 제어기 소유권 확인 |
| REVERSE_CLEAR | 음의 선속도, 각속도 0 | 계획한 후진 거리 도달, 회전 swept volume의 여유 공간 확보 |
| STOP_AFTER_REVERSE | 속도 0 | odom으로 연속 정지 확인 |
| TURN_TO_ROUTE | 선속도 0, 각속도만 | 경로 첫 전진 방향과 차체/Head 정렬 조건 만족 |
| STOP_AFTER_TURN | 속도 0 | 연속 정지, Head/경로 최신성·전방 공간 확인 |
| RETURN_NAV | Nav2에 단일 홈 목표 인계 | 저장 홈 위치·최종 방향 도달 및 실측 정지 |
| RETURNED | 정지 | 작업 결과 기록, 도킹 문맥 해제 |
| BLOCKED / CANCELED | 정지 | 자동 우회 회전·전진 없음. 새 요청에서 현재 상태로 재계획 |

도킹 문맥 해제는 실제 후진·회전 단계 완료 후의 주행 상태를 기준으로 처리한다. 전체 작업의 RETURNED 판정은 복귀 도착 이후다. 중간에 중단되면 완료한 단계와 실제 pose를 보존하여 불필요한 반복 후진이나 책상 옆 회전이 발생하지 않게 한다.

### 3. 후진 거리와 회전 계획

- 현재 8cm FrontRetreat/15cm 도킹 오류 복구는 장애물 회복용이다. 출발 이탈 거리를 그대로 재사용하지 않는다.
- 실제 차체·랙·카메라·주행 자세 팔 형상으로 후진 전체 구간 및 회전 전체 구간의 swept volume을 계산한다. 책상은 상판 아래 충돌 두께도 포함한다.
- 후진 후보 거리와 좌/우 회전을 함께 탐색한다. 후방 이동과 회전 구간 모두 충돌 없는 가장 짧은 실현 가능 후보를 고른다. 거리 상한과 시간 제한은 명시적 설정으로 둔다.
- 설정 초안: 후진 최대 속도 0.05m/s, 회전 최대 0.15rad/s, 각 단계 정지 확인 0.6초, 정렬 오차 2도. 실제 동작 한계는 보호기와 감속 거리를 반영해 결정한다.
- 후진 완료는 시간 추정이 아니라 시작 yaw 축에 투영한 odom 이동량으로 판정한다. 옆밀림·yaw 드리프트가 한계를 넘으면 정지한다. 후진 중 회전으로 보정하지 않는다.
- 후진 중에도 후방 점군·회전 여유를 갱신한다. 후방 관측이 부족하거나 막히면 정지하며, 회전 단계를 앞당기지 않는다.
- 회전은 짧은 각도만 고집하지 않고 양방향 전체 궤적을 검사한다. 회전 중 새 장애물이나 팔 자세 변화가 생기면 중단한다.
- Nav2 경로가 회전 도중 바뀌면 정지 상태에서 방향을 다시 결정한다. 처음 방향이 크게 달라진 경로를 정렬 없이 실행하지 않는다.

### 4. 팔 잠금에서 이탈로 인계

현재 `base_completion_policy: hold`는 사용자 이전 요구에 맞춰 팔 성공 후 잠금을 보존한다. 새 복귀 흐름에서는 해당 작업에 **명시적인 이탈 인계 요청**을 추가한다.

- `return_success`만 믿지 않고 신선한 관절 피드백으로 전체 주행 자세 도달과 정지를 확인한다. 놓기 작업은 EMPTY/정상 place 완료도 필요하다.
- 계획 준비 중에는 잠금을 유지한다. coordinator가 같은 task ID의 전환 요청을 검증하고, 실제 gate의 새 해제/소유권 ACK를 받은 후에만 이탈 속도를 허용한다.
- 잠금 파일 삭제, 무조건 release 기본값 변경, hold 조건 무시는 사용하지 않는다. 작업 ID 불일치·중복 요청·만료된 ACK는 거절한다.
- 인계 순간 다른 teleop/Nav2 명령이 유입되지 않도록 gate는 일반 입력 차단을 유지하고 이탈 제어기의 명령만 허용한다. 최종 watchdog을 단일 출력 소유자로 유지한다.

### 5. P0 완료 기준

- 실제 명령 시퀀스에서 `후진 → 정지 → 순수 회전 → 정지 → 전진 복귀` 순서가 성립한다.
- 후진 중 비영 각속도, 회전 중 비영 선속도, 정렬 전 Nav2 목표 전송이 차단된다.
- 팔 미수납, stale odom/점군, 후방 장애물, 회전 궤적 충돌, 중복 이동 요청, action cancel 지연, 웹/제어기 재시작, 지도/odom 변경을 각각 검사한다.
- 가까운 책상 옆에서 복귀·일반 NAV·새 Detection 명령 어느 경로로도 회전 단계를 먼저 실행할 수 없다.
- 홈 미설정·지도 불일치·작업 중 홈 변경에서는 접근 시작점이나 임의 좌표로 복귀하지 않는다. 등록된 홈의 최종 yaw까지 도달해야 복귀 완료로 판정한다.
- 격리 ROS에서는 가상 센서/보호 응답으로 단계·소유권·lease를 검사한다. 현장 시험은 팔 주행 자세에서 도킹만 수행하는 모드로 시작하고, 후진·회전·복귀를 순서대로 확인한다.

## P1 — 성공한 팔 작업본을 현재 통합 경로로 이식

1. **설정 출처 통합:** 성공 hash의 드라이버·관절·CAN·펌웨어·복귀 후보·실측 depth 조건을 별도 프로파일로 가져온다. 임시 그리퍼 보정은 `nominal_trial`로 표시하고 청사과에 한정한다. 과거 base_link 고정 책상 좌표는 현재 odom 도킹 polygon으로 대체한다.
2. **관측·수납 경로:** 성공 작업본의 rest/경유/관측 자세와 복귀 순서를 현재 연속 스플라인 계획·실행에 결합한다. `return_joints` 도달과 차체 주행용 `rest_joints` 도달을 구분한다. 물체를 들고 랙 쪽으로 접지 않는다.
3. **랙 간격 검사 개선:** 기존 clearance.py를 이식하되 실제 실행 스플라인을 검사한다. 랜덤하게 줄인 mesh vertex 검사만으로 면·모서리 간 충돌을 보증하지 않는다. 형상 파싱 실패·빈 점군을 통과시키지 않고, MoveIt 자기 충돌 및 보수적 거리 검사를 함께 사용한다. 기존 self-contact 예외는 별도 검토 없이 복사하지 않는다.
4. **범용 SAM 2.1 연결:** 이미 있는 tiny checkpoint와 환경을 사용한다. YOLO bbox+SAM 경로를 유지하면서 성공했던 SAM 자동분할 경로를 선택 가능하게 추가한다. 자동분할은 클래스 분류기가 아니므로 요청 ID, coarse 위치, depth, 크기·형상과 여러 프레임 일치로 대상 연계를 확인하고 모호하면 중단한다.
5. **드라이버 소유권:** 현재 관제의 read-only CAN 관절 수신기와 제어 드라이버의 역할·토픽을 명확히 분리한다. 명령 publisher와 모델 JointState 소유자는 단일화한다. 기존 run_pick.sh의 pkill·강제 journal 해제·임시 성공/lease 입력을 가져오지 않는다.
6. **하나의 실행 체계:** 관제센터에서 선택한 프로파일과 동일한 버전의 driver/MoveIt/coordinator/wrist를 실행한다. 팔 작업 결과·수납 완료·베이스 이탈이 동일 task ID로 연결된다.

P1 완료는 먼저 청사과 도킹→집기→놓기→팔 수납→P0 이탈→복귀 1회로 판정한다. 다른 클래스는 기존 규칙을 유지하되 폭·접촉·형상에 맞는 별도 실물 기록을 쌓는다.

## P2 — 개선할 가치가 큰 항목

- **도달 가능성 기반 도킹:** 현재 선호 XY 오프셋에서 실제 IK·관절 한계·랙 간격·관측 시야를 함께 점수화하는 접근 자세 선택으로 확장한다. 도킹 후 손목 재배치를 줄이는 것이 목적이다.
- **주행 자세 기반 collision geometry:** 팔 수납 확인 결과를 차체 보호 및 후진·회전 형상에 반영한다. 팔이 움직이거나 예상 자세를 벗어나면 즉시 정지한다.
- **손목 관측 효율:** 매 프레임 자동분할 대신 요청 시 실행, coarse 위치로 후보 영역 축소, 후보 수 제한, 촬영 지연·p50/p95 계측으로 선택한다. 실제 측정 없이 50ms 달성으로 표현하지 않는다.
- **도킹·복귀 계측:** 전후/좌우/heading 오차, 후진 실측 거리, 최소 회전 여유, 잠금 인계 지연, 단계별 소요 시간과 실패 원인을 한 작업 로그로 남긴다.
- **재시작 복구:** 성공/실패 기록과 도킹/팔/잠금 상태를 함께 복원해 과거 작업 재실행과 잘못된 잠금 해제를 막는다.

## 구현 파일과 순서

1. `SW/control_center/dock_departure.py` 신규: 계획/상태 전이, 후진·회전·복귀 소유권.
2. `navigation_controller.py`, `control_process.py`, `detection_approach.py`: 도킹 문맥 저장, 모든 도킹 후 이동 요청 공통 진입, 상태 IPC.
3. `SW/robot/tracer_safety_watchdog.py`, `manipulation_base_lock.py`, 필요한 메시지 계약: 이탈 단계별 최종 명령 제한과 작업 소유권 전환.
4. `SW/control_center/server.py`, `manipulation_control.py`, `static/*`: 홈 위치·방향·지도 ID 저장 및 현재 위치를 홈으로 등록, 도킹 유지/팔 수납 대기/후진/정렬/홈 복귀/차단 상태와 취소 표시.
5. `SW/manipulation/.../node.py`, `motion.py`, `wrist_frontend.py`, 실물 프로파일: 성공 작업본 기능 이식 및 P0 연결.
6. 변경별 오프라인·격리 ROS 검사, 버전 고정 runtime 설치, 단계별 현장 확인, 커밋과 GitHub main 반영.

각 구현은 현재 실행 중인 로봇 작업과 분리해서 준비한다. 이 계획 자체는 자동 복귀나 팔 실행을 시작하지 않는다.
